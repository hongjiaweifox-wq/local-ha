1演示前准备与检查清单

建议提前一天完成安装和配对；演示当天只做“打开、展示、下发”，避免现场等待重启或网络下载。

CONOW 一体机固件 ≥ 1.2
↔
RS-485 / 网口RTU 或 Modbus TCP
↔
Home Assistant2026.6 或更高
→
分组面板侧边栏 / 设备页跳转

硬件与网络

  • HA 主机已安装并可通过 http://<HA地址>:8123 访问。
  • HA 与设备在同一局域网；如用 RS-485 适配器，USB 已直通给 HA 主机。
  • 设备已在 CONOW ECO App 中完成激活（全新设备未激活时 RS-485 不工作）。
  • 已在 App 中打开 启用外部控制 / ModBus RTU。
  • 准备演示用的连接参数：从站地址 160（0xA0）、波特率 38400、TCP 端口 502。
  • 设备固件为 1.2 或更高 时使用完整的 v2 分组；低于 1.2 也能打开分组面板，只是显示 v1 的 7 个分组。

软件

  • HA 版本满足 hacs.json 要求：2026.6.0+。
  • HACS 已安装并完成 GitHub 授权。
  • Conow Local 已通过 HACS 安装（版本 2.5.0），并已重启 HA。
  • 浏览器已强制刷新，侧边栏能看到 「Conow Local 分组」。
  • 演示账号为管理员（安装集成、重启、HACS 操作都需要管理员权限）。
网络提醒 HACS 安装与下载需要访问 GitHub。如果演示现场网络受限，请提前装好 HACS 与集成，现场只展示“已安装”的界面，或准备手机热点。
演示兜底 没有真机时可用仓库自带的模拟器（见附录），以固件 1.2、v2 寄存器表启动，效果与真机一致。

2安装 Home Assistant

推荐使用 Home Assistant OS；如果演示机已经装好 HA，可跳到下一节。

方式一：Home Assistant OS（推荐）

  1. 准备主机 x86-64 小主机、虚拟机或树莓派均可；建议至少 2 GB 内存、32 GB 存储。
  2. 下载镜像 打开 home-assistant.io/installation， 选择对应硬件的 HA OS 镜像。
  3. 写入启动盘 使用 Balena Etcher 把镜像写入 U 盘或 SSD。写入会清空目标磁盘，请先确认没有重要数据。
  4. 上电并联网 把启动盘插入目标机，用网线接入与设备相同的局域网，然后上电。
  5. 打开首次向导 浏览器访问 http://homeassistant.local:8123；如果无法解析，用路由器里查到的 HA 主机 IP 访问。
  6. 完成初始化 创建管理员账号，设置名称、语言（简体中文）、时区和位置，完成后进入 HA 概览页。
  7. 记录地址 在 设置 → 系统 → 网络 中确认 HA 的 IP，演示时统一使用这个地址。

方式二：Docker（HA Container）

如果演示机已经运行 Docker，可直接启动官方容器：

docker run -d \
  --name homeassistant \
  --restart=unless-stopped \
  --privileged \
  -e TZ=Asia/Shanghai \
  -v /opt/homeassistant:/config \
  --network=host \
  ghcr.io/home-assistant/home-assistant:stable

启动后访问 http://<主机IP>:8123。若使用 RS-485 串口，需要把设备直通进容器，例如追加 --device=/dev/ttyUSB0:/dev/ttyUSB0。

说明 本手册以 HA OS 的界面为准；HA Container 没有加载项商店，HACS 需按下一节的“手动安装”方式处理。

3安装 HACS

HACS 用来从 GitHub 安装自定义集成。它需要 GitHub 账号，并要求 HA 版本满足集成声明的最低版本。

HA OS / Supervised：脚本安装

  1. 打开终端加载项 设置 → 加载项 → 加载项商店，安装并启动 Terminal & SSH（或 Advanced SSH & Web Terminal）。
  2. 关闭保护模式 打开该加载项的 配置，关闭 Protection mode 并重启加载项，否则无法写入 HA 配置目录。
  3. 执行安装脚本 在终端中运行： 
    wget -O - https://get.hacs.xyz | bash -
  4. 重启 Home Assistant 设置 → 系统 → 重启，等待 HA 重新启动完成。
  5. 添加 HACS 集成 设置 → 设备与服务 → 添加集成，搜索 HACS，勾选确认项后提交。
  6. 完成 GitHub 授权 页面会显示一个设备码。打开 https://github.com/login/device，登录 GitHub 并输入设备码，授权后回到 HA 完成。
  7. 确认入口 左侧边栏出现 HACS 即安装成功。

HA Container：手动安装

没有加载项商店时，在 HA 配置目录（通常是 /config）执行：

cd /config
wget -O hacs.zip https://github.com/hacs/integration/releases/latest/download/hacs.zip
unzip -o hacs.zip -d custom_components/hacs
rm hacs.zip

然后重启 HA，并按上面的第 5–7 步添加 HACS 集成、完成 GitHub 授权。

注意 HACS 必须能访问 GitHub；授权失败或一直转圈时，先检查 HA 主机的网络与 DNS，再重试。安装完成后不要删除 config/custom_components/hacs。

4通过 HACS 安装 Conow Local

演示使用仓库 hongjiaweifox-wq/local-ha；如果使用其他仓库地址，替换第 2 步的 URL 即可。

  1. 打开 HACS 集成页 左侧边栏 HACS → 集成。
  2. 添加自定义仓库 点击右上角 ⋮ → 自定义仓库（Custom repositories），填写：
    • 仓库地址：https://github.com/hongjiaweifox-wq/local-ha
    • 类别：集成（Integration）
    点击 添加。
  3. 下载集成 回到 HACS 集成页，搜索 Conow Local，打开条目并点击 下载（Download）。
  4. 重启 Home Assistant 设置 → 系统 → 重启，等待启动完成。
  5. 验证安装 设置 → 设备与服务 → 添加集成，能搜索到 Conow Local 即安装成功。
版本确认 集成版本为 2.5.0，文件位于 config/custom_components/conow_local/。 如果 HACS 提示 HA 版本过低，请先把 HA 升级到 2026.6 或更高。
现场演示建议 下载和重启都比较耗时，建议提前完成本节。现场只需打开 HACS 展示“已下载”，或直接从“添加集成”开始。

5添加设备（三种连接方式）

先选连接方式，再填写对应参数。三种方式的区别只在“HA 如何连到设备”，进入面板后的操作完全一致。

设置 → 设备与服务 → 添加集成 → 搜索 Conow Local，在“连接方式”中选择：

方式 适用场景 必填参数 验证码
Modbus TCP（直连一体机） 一体机自带 Modbus TCP 网口，中间没有转换器 设备名称、主机/IP、TCP 端口 502、从站 160 需要 一体机屏幕上的 6 位码
Modbus TCP（以太网适配器） RS-485 ↔ 以太网转换器，设备仍走 RTU 设备名称、适配器 IP、TCP 端口 502、从站 160 不需要
Modbus RTU（串口） USB 转 RS-485 直接接在 HA 主机上 设备名称、串口路径、从站 160、波特率 38400 不需要

直连一体机（带验证码）

  1. 连接方式选择 Modbus TCP（直连一体机）。
  2. 填写设备名称、一体机 IP、TCP 端口 502、从站地址 160。
  3. 输入一体机上显示的 6 位验证码，提交。
  4. 集成会把验证码写入保持寄存器 0x2701–0x2702（9985–9986）；TCP 直连时该动态验证码每 120 秒刷新一次，设备确认通过后才会创建设备条目。
验证失败 提示“设备校验未通过”时，核对屏幕上的 6 位码是否变化，重新输入；提示“验证码必须是 6 位数字”时，去掉空格或字母再提交。

以太网适配器 / RS-485 串口

  • 适配器方式：适配器的串口侧配置为 38400 8N1，并透传从站地址 160；HA 侧填写适配器 IP 和 TCP 端口。
  • 串口方式：串口路径示例：Linux / HA OS 为 /dev/ttyUSB0，macOS 为 /dev/cu.usbserial-*；Docker 需把设备直通进容器。
  • 无论哪种方式，都必须在 App 中开启 启用外部控制 / ModBus RTU。

添加成功后的固件路由

集成启动时会读取 10062–10063（0x274E）的 4 字节 ASCII 固件版本，并据此选择寄存器表：

固件版本使用的映射效果
≥ 1.2 maps/panel_registers.json（v2） 启用分组面板与面板实体，11 个分组，与定稿表格的「分类」列一一对应，覆盖 10000–10081 与 10100–10189 的全部功能
< 1.2 / 读取不到 maps/registers.json（v1） 照常显示 v1 实体；分组面板显示 v1 的 7 个分组（系统、实时监控数据、运行参数与设备信息、详细监控数据、累计电量、工作策略、实时控制）；「系统」分组把系统状态位掩码拆成待机、故障、充电中、放电中 4 个只读值
演示必须 两种固件都能使用分组面板，但 ≥ 1.2（v2）才有完整分组和面板实体。演示前请在设备页或日志中确认版本，日志会显示 Map: firmware=1.2 -> v2 或 -> v1。

6从设备详情跳转到分组面板

面板有三个入口，演示时建议依次展示：设备页“访问” → 侧边栏入口 → 写入拦截提示。

设置 → 设备与服务Conow Local
→
点击设备进入设备详情
→
点击「访问」设备名称旁
→
分组面板自动选中该设备

入口一：设备详情页「访问」

  1. 打开 设置 → 设备与服务 → Conow Local。
  2. 点击设备卡片或设备名称，进入设备详情页。
  3. 在设备名称旁点击 「访问」。
  4. 浏览器会打开 /conow-local-panel?device_id=…，面板顶部会自动选中这台设备。
为什么用这个链接 该链接由集成写入设备信息，使用 homeassistant:// 同源跳转，不依赖 HA 的内网 IP，换主机名或端口也能正常打开。

入口二：侧边栏

左侧边栏点击 「Conow Local 分组」，在面板顶部工具栏的“设备”下拉框中选择要查看的设备。

入口三：设备页写入拦截

  1. 设备详情页会显示全部可写控件：数值（number）、枚举（select）、开关（switch）和时间（time），但所有控件都拒绝直接下发。
  2. 尝试修改任意一个可写控件并提交。
  3. HA 会弹出提示：“为保证原子性，设备页上的单个控件不会直接下发；请在 Conow Local 面板中整组下发。”
  4. 点击提示里的 「打开面板」 按钮，直接跳转到该设备的面板。
设计原因 计划表、策略、功率限制等寄存器必须整组下发。设备页一次只改一个寄存器，会把一组配置拆成多帧，可能让设备短暂处于不一致状态，因此 v1 与 v2 的设备页写入行为完全一致，统一引导到面板。

7分组面板使用与整组下发

面板按“分组”组织寄存器：只读数据用于展示，可写分组在底部提供“批量下发”。

工具栏与筛选

控件作用
设备切换要查看的 Conow Local 设备
分组只看某个分组，例如“TOU 计划表”
实体按实体名称/编码定位寄存器行
访问权限全部 / 仅可写 / 仅可读
刷新立即重新读取设备数据

分组内容

只读分组

实时监控数据、详细监控数据、运行参数与设备信息、累计电量。

数值直接来自设备，不支持在面板修改。

可写分组

功率与 SoC 设置、实时控制、工作策略、柴发与 DO、基础负载、基础负载计划表、TOU 计划表。

修改后整组下发，连续寄存器合并为一帧 FC 0x10，不连续时按寄存器逐条写入。

编辑与校验

  • number 类型可直接输入或拖动滑块，输入框与滑块双向同步。
  • 超过允许范围会自动限制到边界，并提示“已限制为 …”。
  • 时间寄存器只接受 HH:MM；非法读数会隐藏，需要重新设置。
  • 分组底部会显示“无改动”“请填写完整”“超出允许范围”等状态；不满足条件时“批量下发”不可点击。

批量下发

  1. 修改该分组内需要调整的字段。
  2. 点击分组底部的 「批量下发」。
  3. 面板弹出确认框，只显示分组名称，不再列出全部寄存器值：

    批量下发

    确认把分组「TOU 计划表」写入设备？

    取消 确定
  4. 点击 「确定」；Esc、点击遮罩或「取消」都会放弃本次下发。
  5. 成功后显示“「TOU 计划表」：已下发”；失败会显示设备返回的错误原因。
原子性 同一分组内地址连续的寄存器会合并成一个 FC 0x10 帧；地址有间隔时按计划连续发送多帧，顺序固定，不会只写一半。
数据刷新 面板写入成功后会立即回读并刷新；后台轮询间隔由当前地图决定：v2 约每 30 秒，v1 每 5 秒。两版使用同一个协调器，按活动地图的读取块轮询。

8常见问题排查

按“现象 → 常见原因 → 处理”快速定位。演示现场优先看 HA 的 设置 → 系统 → 日志，过滤 conow_local。

现象常见原因处理
添加集成提示“无法通过 Modbus 连接” 未开启外部控制、从站/波特率不对、A/B 接反、端口被占用 在 App 打开 启用外部控制 / ModBus RTU；确认从站 160、波特率 38400；检查 RS-485 极性与适配器
直连模式提示“设备校验未通过” 验证码过期或输入错误 核对一体机当前屏幕上的 6 位码，重新提交
提示“该设备已经配置过了” 同一连接参数已存在条目 直接使用现有条目；不需要重复添加时先删除旧条目
面板没有分组，提示“分组面板不可用” 固件低于 1.2，且 v1 地址也读不到 检查日志中的 Map: firmware=… -> v1/v2；v1 至少要能读到 10000 和 10100 两个块
面板提示“设备有 Modbus 响应，但地址全部读不到” 固件版本与设备实际提供的映射不一致 确认日志中的 Map: … 与设备/模拟器提供的寄存器表一致；v1 需要 10000–10036 与 10100–10107
设备页修改可写实体没有写入 面板-backed 实体的保护机制 点击提示里的 「打开面板」，在对应分组整组下发
HACS 搜索不到 Conow Local 未添加自定义仓库、类别选错、未重启 重新添加仓库并选择 Integration；重启 HA 后再搜索
HACS 下载失败 / 一直转圈 HA 主机无法访问 GitHub 检查网络、DNS 或代理；也可手动把集成目录放进 custom_components/
面板还是旧界面（例如仍出现浏览器地址行） 浏览器缓存了旧版 JS 强制刷新（Cmd/Ctrl+Shift+R）；确认集成已重启
侧边栏没有「Conow Local 分组」 集成未加载成功，或面板注册失败 重启 HA；查看日志中 conow_local 的 ERROR；确认 HA 版本 ≥ 2026.6
日志关键字 Map: firmware=… -> v2 (panel_registers.json)、 Finished fetching conow_local_panel_… (success: True)、 Control write … addr=…。

9演示流程速查（15 分钟）

按时间轴推进；每一步都给出“要展示什么”和“观众应看到什么”。

时间操作预期效果
0:00–1:30 打开 HA 概览，指出侧边栏 「Conow Local 分组」 观众看到 HA 已就绪、面板入口存在
1:30–4:00 讲安装链路：HA OS → HACS → 自定义仓库 → Conow Local（展示 HACS 中已下载的条目） 理解“本地集成、不依赖云”的安装方式
4:00–7:00 设置 → 设备与服务 → 添加集成 → Conow Local，演示直连 + 验证码（或模拟器用适配器方式） 设备创建成功，实体出现在设备页
7:00–9:00 进入设备详情，点击名称旁的 「访问」 分组面板打开并自动选中该设备
9:00–12:00 面板筛选：只看“TOU 计划表”；修改时间/功率；点击 「批量下发」，确认弹窗点“确定” 提示“已下发”，数值回读刷新
12:00–13:30 回到设备页，尝试修改一个可写实体 出现原子性提示，点击「打开面板」跳回面板
13:30–15:00 展示只读分组（实时监控、累计电量），答疑 观众理解“只读展示 + 可写分组”的结构
控场提示 安装与重启耗时不可控，尽量提前完成；现场重点放在“设备详情 → 访问 → 面板 → 整组下发”这条主线上。

无真机演示：启动模拟器

仓库自带 tools/fake_modbus_server.py，以 v2 寄存器表、固件 1.2 启动，效果与真机一致：

python tools/fake_modbus_server.py \
  --port 1504 \
  --map custom_components/conow_local/maps/panel_registers.json \
  --firmware-version 1.2 \
  --verify-code 123456 \
  --live
  • 模拟器网页状态：http://127.0.0.1:1604/api/state，可确认 map、固件版本与当前验证码。
  • 模拟器会自动加载 v1/v2 两张表：在网页 http://127.0.0.1:1604/ 把 固件版本（10062，0x274E）改成低于 1.2（如 1.1）会立即切换到 v1 控制块，改回 1.2 及以上自动恢复到 v2，无需重启或更换 --map；状态页的 map 字段会实时反映当前使用的表。
  • 切换固件后，HA 侧需要重新加载该集成（或重启 HA）以重新探测固件并重建实体。
  • 在 HA 中添加集成时选择 Modbus TCP（以太网适配器）：主机填模拟器所在机器 IP（同机可填 127.0.0.1），端口 1504，从站 160，不需要验证码。
  • 模拟器默认应答任意从站地址；如需严格匹配，追加 --slave 160。
  • 直连演示时，验证码输入 --verify-code 指定的值（示例为 123456）；状态页会显示当前验证码。
